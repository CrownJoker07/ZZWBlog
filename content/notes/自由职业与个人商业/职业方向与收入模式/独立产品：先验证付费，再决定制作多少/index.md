独立产品可以是软件、模板或资料工具。开始前先找出：**谁在什么场景遇到问题，目前怎样解决，为什么愿意换成你的方案**。完成制作只是其中一步，还要有人找到、购买、使用并愿意继续使用。

## 用具体经历代替口头赞同

例如想做“自由职业项目回款管理工具”，可以问潜在用户：上一次漏催款是什么时候，现在用什么记录，出了什么问题，处理一次花多久，谁能决定购买。

Eric Migicovsky 在 [YC《How to Talk to Users》](https://www.youtube.com/watch?v=MT4Ig2uqjTc) 中建议围绕用户的实际生活、具体经历与已有解决方法交流。本文把这套访谈方式用于个人产品；几次访谈只能帮助找线索，不能估算整个市场需求。

## 先交付最小但完整的结果

先做一张能记录付款节点、筛出逾期项目的表格，让有对应问题的人实际使用。暂不做团队权限、自动发票、复杂仪表盘。

Paul Graham 在[《Do Things that Don’t Scale》](https://www.paulgraham.com/ds.html) 中强调，早期需要主动寻找用户，也可能先手工完成部分工作。这是创业经验；本文采用的是主动观察使用、缩小制作范围的做法，不据此承诺成功率。

## 一轮试做怎样限定投入

下面是一个试验设计示例，天数和价格都不是行业标准：

| 阶段 | 行动与产出 |
| --- | --- |
| 前三天 | 联系有回款管理问题的人，记录最近一次真实经历和替代方法 |
| 接下来四天 | 做出可独立使用的表格，写明适用范围与操作说明 |
| 再用一周 | 提供演示和试用，观察能否完成任务，尝试明确价格的销售 |
| 复盘 | 核对付费、退款、使用困难与支持时间，决定继续还是缩小范围 |

例如用 99 元测试一次性模板销售，应在购买前说明包含哪些文件、兼容环境、更新和售后范围、交付与退款安排。不承诺尚未完成的功能，试售也不能代替应履行的交易义务。

## 定价与渠道一起验证

假设售价 99 元，渠道和支付等每单变动费用共 9 元，剩余 90 元，尚未扣除税费、售后、推广与制作成本。如果每单需要两小时辅导，就需要把辅导单独定价，或改进说明与产品，不能直接把 90 元当净利润。

早期渠道可以从已经访谈的用户、相关专业社群、已有内容受众中选择，但要遵守社区推广规则。必须记录用户从哪里来，否则难以判断下一批客户怎样获得。

## 根据行为决定下一版

| 观察到的情况 | 优先处理 |
| --- | --- |
| 口头认可，但不愿试用 | 检查问题是否重要、是否找对人、开始使用是否麻烦 |
| 愿意试用，但没有完成关键任务 | 观察操作卡点，检查是否真正解决问题 |
| 使用后不买，已有免费方案足够 | 重新判断付费价值，不急着堆功能 |
| 付费后反复使用，并提出相似需求 | 优先处理影响核心任务的问题，再测试扩展 |
| 每单都要大量定制和陪同 | 按服务业务核算时间，或缩小产品承诺 |

**首单说明有人愿意为一次交易付费；持续盈利还需要重复获客、成本可控和可靠交付**。复盘时把退款、故障、售后和维护一并算入。
