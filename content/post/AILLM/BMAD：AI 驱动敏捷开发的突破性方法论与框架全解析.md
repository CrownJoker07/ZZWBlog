BMAD 是一个 **AI 驱动的敏捷开发框架**，全称为 **Build More Architect Dreams**（也称为 Breakthrough Method of Agile AI Driven Development）。
提供了结构化、经过验证的敏捷开发工作流

BMAD 采用了几种创新的架构模式 2。步骤文件架构：每个步骤都重新加载上下文，避免“中间迷失”综合症，确保 AI 在长流程中始终保持清晰的执行方向 2。微文件架构：采用顺序对话编排，降低单次交互的复杂度 2。三模式工作流：每个工作流都具备创建、验证、编辑三种能力，确保产出质量 2。四模式工作流：简报、创建、编辑、验证，提供更完整的生命周期管理 2。这些架构模式共同保障了 BMAD 在复杂场景下的可靠性和可维护性。

Agentic Coding 的典型工作流 [4]
以前（Vibe Coding）：
你 → "帮我写一个登录功能" → AI 生成代码 → 你复制粘贴 → 改改改

现在（Agentic Coding）：
你 → "帮我实现用户认证模块，需要支持 OAuth 和 JWT" 
    ↓
AI Agent → 先出计划："我打算这样做：1. 创建 AuthService 2. 实现 OAuth 流程..."
    ↓
你 → 审核计划，通过
    ↓
AI Agent → 自主执行代码实现 → 写测试 → 自测
    ↓
你 → Review 代码质量 → 通过/打回

```
    (具体框架)              (具体框架) (具体工具)          (具体工具)
```

**更准确的理解应该是**：

| 你的理解 | 问题点 | 修正 |
|---------|--------|------|
| BMAD 作者 = Agentic Engineering | ✗ Agentic Engineering 是 Karpathy 提出的概念，不是某个人 | BMAD 作者是 Agentic Coding 的**实践者/布道者** |
| 用 BMAD = Agentic Coding | ✓ 基本正确 | BMAD 是实现 Agentic Coding 的一种**具体方式/框架** |

**一句话总结**：

- **Agentic Engineering** = 理论（你要具备什么能力）
- **Agentic Coding** = 实践（你怎么用 Agent 编程）
- **BMAD** = 工具（你用什么东西来实践）

## 二、如何学好 Agentic Engineering？

基于 Karpathy 的论述和行业实践，Agentic Engineering 的核心能力可以拆解为 **6 大维度**：

### 能力一：系统架构能力

| 是什么                    | 为什么重要                  | 怎么练                                                  |
| ---------------------- | ---------------------- | ---------------------------------------------------- |
| 能够把复杂需求拆解为合理的模块、层次、数据流 | Agent 不会帮你做架构取舍，你得自己决定 | - 学习经典架构模式（MVC、微服务、DDD）<br>- 阅读开源项目源码<br>- 试着手绘系统架构图 |

**核心思维**：**"先想再让 Agent 做"**，而不是"让 Agent 想到什么做什么"。

```
❌ Vibe Coding 思维：
"帮我写一个电商系统" → Agent 想到哪写到哪 → 代码散乱

✅ Agentic Engineering 思维：
"这个电商系统需要：用户模块、商品模块、订单模块、支付模块
 用户模块用 JWT、商品模块用 Elasticsearch、订单用事务..."
 → Agent 按架构执行 → 代码结构清晰
```

### 能力二：Prompt / Intent Spec 写作能力

| 是什么                     | 为什么重要                       | 怎么练                                                                                                    |
| ----------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------ |
| 把需求清晰、无歧义地传达给 Agent 的能力 | 模糊的需求 → 模糊的代码；清晰的规格 → 可靠的产出 | - 学习结构化表达（Goal + AC + Constraints + Non-goals）<br>- 参考 BMAD 的 Intent Spec 模板<br>- 养成先写文档再让 Agent 动手的习惯 |

**Intent Spec 模板**：

```markdown
## Goal（目标）
我要构建一个用户认证模块

## Acceptance Criteria（验收标准）
- [ ] 支持 Email + 密码登录
- [ ] 支持 OAuth（Google、GitHub）
- [ ] 使用 JWT Token，24小时过期
- [ ] 密码加密存储（bcrypt）

## Constraints（限制条件）
- 技术栈：Node.js + Express + MongoDB
- 不使用第三方认证服务
- 必须包含单元测试覆盖率 > 80%

## Non-goals（明确不要）
- 不要短信验证码登录
- 不要社交分享功能
```

### 能力三：代码 Review 能力

| 是什么 | 为什么重要 | 怎么练 |
|--------|-----------|--------|
| 一眼看出 Agent 生成代码的问题 | AI 代码的 churn（写了又改）比人工高 2 倍；你需要把关 | - 学习常见代码异味（Code Smell）<br>- 理解安全漏洞模式（SQL注入、XSS等）<br>- 养成看 diff 的习惯 |

**Agent 生成代码的常见问题**：

| 问题类型 | 典型表现 | 怎么发现 |
|---------|---------|---------|
| **幻觉** | 调用不存在的 API、使用不存在的库 | 仔细看 import 和依赖 |
| **安全** | API Key 硬编码、SQL 拼接、没做输入验证 | 安全扫描 + 人工检查 |
| **风格** | 命名不一致、格式不统一 | 用 linter 检查 |
| **逻辑** | 边界条件没处理、异常没捕获 | 仔细看 edge case |

### 能力四：系统设计能力

| 是什么 | 为什么重要 | 怎么练 |
|--------|-----------|--------|
| 理解技术选型的 Trade-off，能做取舍 | Agent 可以写代码，但不会帮你决定"用 MySQL 还是 PostgreSQL"、"用 REST 还是 GraphQL" | - 学习数据库原理<br>- 理解不同方案的优缺点<br>- 参与技术方案评审 |

**常见技术取舍判断**：

| 场景 | 选项 | 选哪个？ | 为什么 |
|------|------|---------|-------|
| 日志系统 | ELK vs Loki | Loki | 数据量不大时更简单 |
| 缓存 | Redis vs Memcached | Redis | 支持更多数据结构 |
| 前端框架 | React vs Vue | 取决于团队 | 没有绝对优劣 |
| 认证 | Session vs JWT | JWT | 分布式更友好 |

### 能力五：产品 sense

| 是什么 | 为什么重要 | 怎么练 |
|--------|-----------|--------|
| 知道"该做什么"比"怎么做"更值钱 | Agent 可以实现任何功能，但你得告诉它实现什么 | - 多参与产品讨论<br>- 学习数据分析<br>- 理解用户需求 |

> **"AI 时代，最稀缺的不是能写代码的人，而是能定义好问题的人。"**

### 能力六：质量工程能力

| 是什么 | 为什么重要 | 怎么练 |
|--------|-----------|--------|
| 设计测试策略、建立质量门禁 | Vibe Coding 的致命伤是没有品质机制 | - 理解测试金字塔<br>- 掌握 CI/CD 基础<br>- 学会用工具（SonarQube、Snyk） |

## 三、学习路径推荐

### 阶段一：入门（1-2 周）

| 任务 | 目的 |
|------|------|
| 1. 理解 Agentic Coding vs Vibe Coding 的区别 | 建立概念框架 |
| 2. 学会用 Cursor/Windsurf 的 Agent 模式 | 熟悉工具 |
| 3. 尝试写第一个 Intent Spec | 练习需求表达 |

### 阶段二：实践（1-2 个月）

| 任务 | 目的 |
|------|------|
| 1. 用 Agentic Coding 方式完成 2-3 个小项目 | 积累经验 |
| 2. 学习读懂 Agent 生成的代码，学会 Review | 培养审查能力 |
| 3. 了解 BMAD 框架，尝试应用到项目中 | 理解方法论 |

### 阶段三：进阶（3-6 个月）

| 任务 | 目的 |
|------|------|
| 1. 学习系统设计和架构模式 | 提升决策能力 |
| 2. 建立自己的 Agentic Engineering checklist | 形成方法论 |
| 3. 参与复杂项目，练习技术选型 | 积累判断力 |

### 阶段四：精通（持续）

| 任务 | 目的 |
|------|------|
| 1. 关注前沿（Karpathy、Cursor 博客等）| 跟上趋势 |
| 2. 输出分享，构建个人影响力 | 巩固理解 |
| 3. 教别人，形成知识闭环 | 深化理解 |

## 四、核心心法

最后，用一句话总结 Agentic Engineering 的核心心法：

> **"把 AI 当作一个很强但不懂你业务的 Junior 开发者。你是 Senior + PM 的合体：你要清晰地告诉它要什么（Spec），要在它做完后检查质量（Review），要在它迷茫时给方向（Architecture）。"**

记住：**AI 越强，对驾驭 AI 的人要求越高，而不是越低。** [1][4]
